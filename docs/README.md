# OctoAcme Project Management Docs

This collection is the onboarding entry point for OctoAcme's project management practices. Together, these guides describe a lightweight, iterative delivery model that starts with project initiation and stakeholder alignment, moves through planning and dependency mapping, and then supports execution, tracking, release, and continuous improvement.

OctoAcme's lifecycle emphasizes clear ownership, shared visibility, and measurable outcomes. Work begins with a one-pager, stakeholder list, high-level milestones, and initial risks; then shifts into prioritized backlogs, acceptance criteria, estimates, Definition of Done, and release planning. During delivery, teams use a project board, regular standups and syncs, pull request reviews, CI checks, manual QA where needed, and escalation paths to keep work moving and quality visible.

The process is supported by defined roles and communication habits. Project Managers coordinate timelines, risks, dependencies, and stakeholder updates; Product Managers set goals, prioritize work, and measure outcomes; developers and QA/testing contributors build, review, and validate deliverables against acceptance criteria. Risks are tracked in a shared register and reviewed regularly, while release checklists, smoke tests, rollback planning, and retrospectives help the team reduce delivery risk and turn lessons learned into actionable improvements.
